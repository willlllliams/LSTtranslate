# 服务器模型的识别误差分析

## 结论

本节至“可复现配置”的数据对应 beta.3。后续词级拼行改进的对照见本文最后一节。

本组截图中，服务器模型效果较差的主因是检测输入尺度与词框后处理的组合。切换服务器模型后，程序仍保留通用 OCR 产线的缩放配置。博客原图以接近原始分辨率进入检测器，服务器检测器把五行正文切成 55 个词框，同时漏检两个单词；几何归一化继续把部分词框拼成跨行小段，扩大了阅读顺序误差。

将服务器检测输入改为长边最多 960 像素，正文检测框从 55 个减少到 9 个。博客页的归一化文字准确率从 84.93% 提升到 100%，人工标注的 19 个单元全部召回，粘连和拆碎均为零。只更换服务器识别模型时，博客页准确率与轻量模型相同。因此，识别模型容量解释不了这一轮差异。

附加组件页使用同一缩放参数时，文字准确率也达到 100%，仍有一个输出段关联两个标注单元。960 这一参数已经解决博客页问题，后续调整仍需同时满足附加组件页的边界约束。

## 样本与控制变量

实验使用用户提供的两张英文 PNG，博客页为 1908 × 1150，附加组件页为 1827 × 924。文件哈希与人工标注见 `tests/fidelity/fixtures/sources.json` 和 `*.expected.json`。早期博客 WebP 经过有损压缩，该样本上的 84.04% 分数由原始 PNG 实验取代。

运行环境为 PaddleOCR 3.7.0、PaddleX 3.7.2、PaddlePaddle 3.3.1。全部对照使用 CPU、4 个推理线程、文本模式、相同清洗和归一化代码。模型名称、请求选项、原始输出与测量结果保存在 `tests/fidelity/fixtures/server/`。

检测模型负责给出文字区域，识别模型负责读取裁剪区域中的文字。实验分别更换这两个环节，再改变检测尺寸与外扩系数。文字准确率使用 `ocr-quality.md` 中的归一化编辑距离，忽略大小写、空格和标点；达到 100% 表示标注中的字母和数字完整，原始结果仍有空格与标点差异。

## 交叉实验

下表均为博客原始 PNG 的结果。默认尺度表示保留产线配置；正文框数统计正文五行范围内的原始文本检测框。

| 检测模型 | 识别模型 | 检测尺度或外扩 | 正文框数 | 归一化文字准确率 | 拆碎单元 |
|---|---|---|---:|---:|---:|
| mobile | mobile | 默认 | 12 | 99.82% | 0 |
| mobile | server | 默认 | 12 | 99.82% | 0 |
| server | mobile | 默认 | 55 | 84.75% | 2 |
| server | server | 默认 | 55 | 84.93% | 2 |
| server | server | 外扩 1.2 | 55 | 69.68% | 2 |
| server | server | 长边最多 1280 | 37 | 96.99% | 2 |
| server | server | 长边最多 960 | 9 | 100.00% | 0 |

只换识别模型，检测框数量不变，博客准确率不变；只换检测模型，框数增加到 55，准确率降到 84.75%。改用两套服务器模型后，仍是 55 个框。该对照把主要误差定位到检测器及其输出后的处理。

## 输入尺度的实际来源

`lst/workers/ocr_worker/paddle_config.py` 的 `_configure_ocr` 替换模型名称，保留产线的检测尺寸字段。本环境的 PaddleX `configs/pipelines/OCR.yaml` 默认选择 PP-OCRv6，检测参数为 `limit_side_len: 64` 与 `limit_type: min`。项目显式选用 PP-OCRv5 模型，项目参数值为 0 和 `default` 时，`predict_kwargs` 跳过这两个参数，因此通用产线中的值继续生效。

`min` 约束短边的最小长度。博客短边为 1150，大于 64，不发生等比例缩小；处理器只把边长对齐到 32 的倍数，检测输入约为 1920 × 1152。选择 `max` 和 960 后，长边先缩小到 960，网络输入为 960 × 576。

两者的网络输入面积比为：

$$
\frac{1920\times1152}{960\times576}=4.
$$

缩小后的正文以更连续的区域进入检测后处理，原始结果从词级碎框转为行内片段。该因果判断来自同一原图、同一模型、只修改尺度的对照结果。模型训练数据中哪种排版因素导致响应改变，当前实验没有直接测量。

PaddleOCR 的[官方性能说明](https://www.paddleocr.ai/main/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5.html)也按明确的检测尺度及测试集报告结果。官方跨场景均值与本项目两页截图属于不同评测，模型名称不能替代实际输入尺寸的核对。

## 检测漏字与后处理顺序错误

默认服务器检测结果的正文第一行缺少 `working`，第二行缺少 `Thunderbird`。这两个词共 18 个字母，原始框列表中没有覆盖它们的有效识别结果。服务器识别模型不能恢复没有送入识别器的区域。

为分离检测损失与顺序错误，诊断工具按原图五条正文基线分组，再按横坐标排列原始框。这一步使用人工已知的基线，只用于定位问题。默认服务器组合的正文编辑距离为 18，生产归一化后变为 85；长边最多 1280 时，原始框按基线恢复后的编辑距离为 0，生产结果仍有 12 个编辑错误。后者直接证明剩余损失发生在后处理。

横向拼行的字高规则按实际着墨高度比较。第一行 `scenes` 的着墨高度为 13 像素，`laying` 为 22 像素，两者属于同一字号，却因字形是否带上伸和下伸部分而相差 69%。这超过当前 30% 的高度容差，导致行内片段被拒绝拼接。漏掉 `working` 后，相邻片段之间另有 91 像素空隙，也超过横向拼接上限。

横向拼接失败后，`_link_rows` 将上下邻近的局部框组成小段。例如 `The team has been` 与下一行的 `foundation for the` 合并，其右侧仍留下其他小段；按小段排序后，正文顺序随之改变。单独关闭栏间空白判断，默认服务器组合的正文编辑距离仍为 85，排除了把该问题归结于 `_in_gutter` 的解释。缩小外扩系数后，生产正文编辑距离升至 145，而检测与识别侧仍为 18。

采用长边最多 960 的服务器组合后，原始基线恢复与生产结果的正文编辑距离均为 0。后续改进的重点是让归一化同时适应词级与行级检测，减少正确文字因分段顺序丢分的问题。

## 可复现配置

博客页已经验证的服务器配置如下：

```toml
[ocr_paddle]
detection_model = "PP-OCRv5_server_det"
recognition_model = "PP-OCRv5_server_rec"
text_det_limit_side_len = 960
text_det_limit_type = "max"
text_det_unclip_ratio = 1.5
```

beta.3 保留轻量模型的默认配置。该模型在两页的全部标注单元上均被召回，检测器产生的片段也更适合当前几何处理；服务器参数作为明确可选择的配置保留。

运行 `python -m tests.fidelity.tune paddle-default paddle-rec-server paddle-det-server paddle-server` 可以复现交叉对照及尺寸实验。运行 `python -m tests.fidelity.server_analysis` 可从保存的原始结果重新计算正文框数、人工基线重建误差与生产误差。离线质量回归包含服务器长边 960 的博客样本。

## 1.0 开发中的词级拼行改进

横向拼行改为结合检测框高和笔画宽度判断字号。`scenes` 与 `laying` 的着墨高度虽然相差很大，笔画宽度仍接近，因此可以恢复到同一文字行。纵向分段继续保留字号与笔画的约束。

片段之间的较宽空隙需要原图证据：前景色、背景色接近，间隙中有足够宽的文字笔画，且两端中间没有其他已识别片段。不同背景的按钮、灰色图标、窄分隔线和空白不作为漏检词的连接证据。该步骤恢复可用词语的顺序，原始检测漏掉的词仍计为漏字。

几何判断的栏缝另用原图前景投影确认。邻行中的可见笔画穿过候选栏缝时，保留横向拼行；持续留白时保持两栏独立。测试同时覆盖真两栏、假栏缝、相邻导航项、不同字号和漏检词。

| 配置 | 原始正文编辑误差 | beta.3 生产正文误差 | 当前生产正文误差 | 当前整页归一化文字准确率 |
|---|---:|---:|---:|---:|
| mobile 检测、mobile 识别 | 1 | 1 | 1 | 99.82% |
| mobile 检测、server 识别 | 1 | 1 | 1 | 99.82% |
| server 检测、mobile 识别 | 19 | 86 | 19 | 96.63% |
| server 检测、server 识别 | 18 | 85 | 18 | 96.81% |
| server、外扩 1.2 | 18 | 145 | 18 | 96.81% |
| server、长边最多 1280 | 0 | 12 | 0 | 99.82% |
| server、长边最多 960 | 0 | 0 | 0 | 100.00% |

评估按 `OcrCompleted.segments` 的生产阅读顺序拼接同一标注单元的片段。词框上边缘会随字形相差数个像素，按顶边再次排序会颠倒同一行的左右片段；回归同时检查正确生产顺序不扣分、反转生产顺序仍扣分。历史 beta.3 的正文误差另从该版本源码重建，表中的改进同时成立于生产顺序与人工基线对照。

长边最多 1280 的正文顺序已完整恢复，整页剩余 1 个编辑错误来自日期单元。外扩 1.2 的正文仍拆成六段，漏检词间隙超过拼行上限，局部词间空白还会形成假栏缝；其可用文字的生产顺序已正确，18 个编辑错误均来自原始漏字。该配置作为分段边界样本保留。默认四种引擎在原始两页上的既有内容与分段指标保持 beta.3 水平。

长边最多 960 的服务器配置在两页共 98 个标注单元上，归一化文字准确率、单元召回率和独立匹配率均达到 100%，误合并与误拆分为零。附加组件页中的大写标签和首字母大写链接，原始 OCR 连成 `MOSTPOPULARAll`；归一化先提出大小写边界，再由原图投影间隙、颜色及字号确认拆分。没有控件间距的缩写词仍保持完整。原始空格与标点差异、三个额外检测框继续保留，指标中的 100% 不表示逐字符完全相同。
