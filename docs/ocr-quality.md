# 参考截图的识别与版面质量

## 样本与标注

测试集使用两组英文截图与繁体中文参考图：附加组件页有 79 个文字单元，博客页有 19 个文字单元。标注位于 `tests/fidelity/fixtures/*.expected.json`，记录英文原图坐标、可见原文、参考译文和单元类别。菜单、标题、正文、分类、评分与计数分别标注。

四张 PNG 与用户附件逐字节一致，原图尺寸及 SHA-256 记录在 `sources.json`。识别缓存另存源图哈希，读取时校验哈希和尺寸；更换图片后必须重新推理。早期目录中的 WebP 为转换样本，当前验收使用 PNG。

英文原图与中文参考图的视口、裁剪范围和语言长度不同。位置指标使用英文原图上的标注框，中文参考图用于核对内容层级与译文布局。原图边缘已经裁掉的文字按可见部分标注，例如博客右上角的 `GET THU`。

## 指标定义

内容比较保留字母和数字，忽略大小写、空格、标点与星形评分符号。这个指标称为归一化文字准确率。它衡量菜单名称、正文、数字等可读内容；标点、大小写和评分图形需要结合原始结果与覆盖图检查。

输出段与标注框的交集至少覆盖较小框面积的一半时，两者建立关联。一个输出段关联多个标注单元，计为粘连；一个标注单元关联多个输出段，计为拆碎。内容指标与分段指标分别计算。

设第 $i$ 个标注的归一化文本为 $s_i$，长度为 $n_i$；与它关联的输出段按上到下、左到右拼成候选文本 $t_i$。令 $d_i$ 为 $s_i$ 与 $t_i$ 任意连续子串之间的最小编辑距离。候选文本的其他单元前后缀在内容比较中跳过，粘连由独立指标计分。

归一化文字准确率为：

$$
A=1-\frac{\sum_i d_i}{\sum_i n_i}.
$$

满足 $d_i\leq 0.15n_i$ 的单元计为召回。独立单元匹配还要求这个单元与输出段一一对应，且包围盒交并比（Intersection over Union，IoU）不小于 $0.5$。

评分单元的标注框包含星形和计数。RapidOCR 在其中两处只返回计数框，文字内容正确，框与整个评分区域的 IoU 低于 $0.5$，因此附加组件页的独立单元匹配率为 97.5%。这个差异保留在指标中。

## 改进结果

主进程现在结合原图的文字颜色、笔画粗细、间距和对齐整理文字单元。版面模型粘成整栏的菜单会被拆开，扩展名称、分类和评分分别处理；连续正文仍合并为段落。

颜色计算按亮度对比度加权，减少 Windows ClearType 彩色边缘对短词颜色判断的影响。短标题和链接粘在同一行时，根据文字投影定位已有词语，再在颜色或明显字号、间距变化的位置拆开。编号与后面的列表文字保持在同一行。

原图像素通过归一化上下文传入，跨进程识别结果格式保持原样。没有像素证据时使用几何关系与选定的段落策略。设置中的“整理文字单元”控制该步骤，PaddleOCR 版面模式的流程图同步展示这一环节。

| RapidOCR，附加组件 | 100.00% | 100.0% | 97.5% | 0 | 0 |
| RapidOCR，博客 | 100.00% | 100.0% | 100.0% | 0 | 0 |

RapidOCR 与 PaddleOCR 版面模式已用真实 OCR 子进程、生产代码中的 `OcrModule` 和原生 Windows 覆盖窗口复测。RapidOCR 的单次 OCR 观测耗时为附加组件页 1.83 秒、博客页 1.63 秒；PaddleOCR 版面模式为 7.56 秒和 6.35 秒。耗时使用本机 CPU、8 个推理线程，排除模型加载；同机还有低优先级的构建和测试任务，因此这些数值只记录此次观测。

改进前，PaddleOCR 版面模式在两页的独立单元匹配率分别为 2.5% 和 57.9%；RapidOCR 分别为 16.5% 和 57.9%。主要差异来自整栏菜单、卡片内容与顶部导航的粘连。

## GitHub 弹窗与组织页面

新增三张用户原始 PNG：组织页面 2288×1169、清晰弹窗 641×279、缩略弹窗 218×95。原图哈希写入 `tests/fidelity/fixtures/sources.json`，四种引擎分别保存原始识别输出。组织页回归检查说明行保持完整；清晰弹窗人工标注标题、正文、文档链接和两个按钮，共五个文字单元。

PaddleOCR 版面模式的清晰弹窗原先被归一化层拆成三段。原始输出把第二行分成两个正文片段，还带一个 3 像素高的冒号。拼行后把这个标点计入行高中位数，行高降为 14 像素，相邻正文行因此未通过字号判断。排除附属标点后，三行正文合为一个段落；标题、链接和按钮保持独立。

| 清晰弹窗引擎 | 归一化文字准确率 | 五个单元召回率 | 正文输出段数 | 拆碎单元 |
|---|---:|---:|---:|---:|
| RapidOCR | 100.00% | 100% | 1 | 0 |
| PaddleOCR 文本模式 | 100.00% | 100% | 1 | 0 |
| PaddleOCR 版面模式 | 99.45% | 100% | 1 | 0 |
| Windows OCR，英语 | 95.60% | 80% | 1 | 1 |

准确率仍采用去除空格、标点并统一大小写的原有计算方法。PaddleOCR 版面模式在正文中多识别了一个字母 I；Windows OCR 的“Create repository”按钮漏字且拆成两个框。这些错误均保留在原始输出和指标中。四种引擎的正文保持完整，只证明段落边界正确；字符准确率和按钮识别需要分别判断。

缩略弹窗中，RapidOCR 的正文保持一段，但字符识别有误；PaddleOCR 出现漏字、漏行，Windows OCR 没有返回文字。该图作为小字识别限制保留，不能按正文合并成功计为文字识别成功。

设置路径为“截屏与识别 → 结构归一化 → 段落合并模式”。默认智能段落结合行尾句末标点和间距判断续行，紧密排列的多个完整句子保留在同一段。用户可以切换几何、按句或连续正文模式，并在高级参数中修改续行间距和句末标点。语句策略作用于相邻视觉行，行内句子维持原有顺序。

覆盖窗口已移除引擎详情浮窗与来源色条；旧来源标记配置读取后丢弃。原生 Windows 覆盖图采用固定人工译文验证排版，正文是一段，且没有文字截断。固定译文用于隔离翻译措辞对布局的影响。

## Windows OCR 自动语言

Windows 的系统识别器一次只使用一种语言。旧自动模式按用户首选语言选择；本机首选为 zh-Hans-CN，因此两张英文原图被中文识别器处理。新版自动模式用已安装的英文与一种中日文识别器互补，分别处理文字系统与位置；指定语言继续使用单识别器。

| 英文页面 | 旧自动模式准确率 | 新自动模式准确率 | 新自动模式召回率 | 新自动模式拆碎单元 |
|---|---:|---:|---:|---:|
| 附加组件 | 94.43% | 99.36% | 97.5% | 0 |
| 博客 | 98.23% | 99.47% | 100% | 0 |

新结果由真实 OCR 子进程生成，原始缓存为 `windows-auto-*.json`，与显式英语配置分别保留。此次 CPU 观测耗时为附加组件页 0.33 秒、博客页 0.20 秒，不含进程启动。单次观测用于记录本机开销，不代表其他机器的速度。

原始两张繁体中文图也保存了英文和中文候选，缓存绑定原图哈希。回归逐词检查中文识别器已有的中日文文字与位置都保留；人工标记的评分星形区域排除误识别的重复汉字。该检查证明互补过程没有丢掉已识别中文，文字本身的准确率需要独立标注。

纯英文、纯中文、同一行混排、英文主体与中文标题四种截图通过真实系统 OCR 测试。完整应用的自动化截图测试分别使用英语和自动配置，均经过真实 Windows OCR 与本地 NMT 进程，并验证译文、覆盖、复制和键位操作。

中英混排的精确文字回归使用固定的原生 Windows 字体截图，避免 Qt 离屏平台的字形栅格差异改变输入。另用动态生成的宽幅中文图验证系统纠偏坐标：本机识别器报告 2° 时，原始词框比实际着墨位置下移约 20 像素。后端现按系统角度绕图像中心还原词框四角，再映射回截图像素。

系统坐标约定见 [TextAngle 文档](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrresult.textangle)。图像中心为 $(c_x,c_y)$，系统词框角点为 $(x,y)$，角度为 $\theta$；截图坐标向右、向下为正，还原为：

$$
x'=c_x+\cos\theta(x-c_x)-\sin\theta(y-c_y),
\qquad
y'=c_y+\sin\theta(x-c_x)+\cos\theta(y-c_y).
$$

四个角点分别还原后，以横纵坐标最小值和最大值构造轴对齐包围盒。缩放、向外取整和截图边界裁剪随后执行。空角度与零角度保持原框，正负角度均由回归约束。

自动模式依赖系统已安装的语言包。英语和一种中日文之间的选择按行进行，再按词的位置去重；短字与同形字仍有歧义。精确指定语言会关闭互补选择。语言策略实现与限制见 `technical-debt.md`。

## 参数比较

真实推理比较了 RapidOCR 默认参数、较小外扩系数、较高检测阈值、更大检测输入，以及 PaddleOCR 的轻量模型、服务器模型和较小外扩系数。参数、原始输出与耗时由 `tests/fidelity/tune.py` 保存。

原始 PNG 上，RapidOCR 默认模型的内容准确率与召回率均为 100%，当前版本保留这些默认参数。早期 WebP 参数实验中，缩小外扩系数、提高检测阈值损失了部分文字，增大检测输入增加了额外框；该轮数据只作为探索记录。

服务器版使用原始 PNG 重新进行检测与识别模型交叉实验，原因分析见 `docs/server-ocr-analysis.md`。服务器模型的结果随检测输入尺寸改变，不能将早期 84.04% 的转换样本分数作为模型的固有精度。

## 覆盖窗口

版面检查使用固定参考译文，使措辞变化与识别、排版变化分开。它验证识别内容和覆盖布局，真实翻译引擎的译文质量另行评估。

无需翻译的纯数字和符号区域保留原图像素。评分星形保持原来的颜色，图标被识别成 `99` 时显示原图中的引号图形。其余译文遵循现有覆盖窗口要求：模糊底图，并按整体亮度使用黑字或白字。

原生覆盖图使用 Windows 字体渲染。RapidOCR 的两张覆盖图均未出现文字截断。图像和逐段字号记录输出到 `data/tmp/fidelity/`。

绘制框布局增加了宽高倍数、内外边距、横纵对齐和自动扩框选项。默认目标字号为原文估算字号的 1.1 倍，在截图边界和相邻内容允许的空间内同时扩宽、扩高，自动扩框上限为手动调整后尺寸的 4 倍。固定横向范围的模式保持左右边界，仅增加高度。原始识别框始终保留，反复调整参数不会累计扩大。

这组默认参数分别在 Windows 10 与 Windows 11 原生字体下验证了扩展列表、博客和清晰 GitHub 弹窗三个样本。92 个需要翻译的文字框全部完整显示，最终字号均达到原文估算字号。该结果使用固定参考译文，证明这些样本的布局达标；原文真实字体未知，字号比较以识别行框和字形测量的估算结果为准。空间更紧或译文更长时，绘制框仍受边界和避让约束，字号会相应降低。

布局回归命令为 `python -m pytest tests/fidelity/test_box_layout.py tests/ui/overlay/test_box_layout.py tests/ui/settings/test_box_layout.py`，设置 `QT_QPA_PLATFORM=windows` 使用原生字体。逐框记录包含原文估算字号、最终字号、绘制框和截断标记。

## 验证与复现

1.0 的完整回归为 4554 项通过、12 项条件跳过。类型检查无错误或警告，代码规范与格式检查通过，八项依赖约束通过。三项主题测试因离屏平台能力跳过，原生 Windows 补测全部通过；其余为八项按需截图测试和一项 CUDA 依赖条件测试。

RapidOCR、PaddleOCR 版面模式和长边 960 的服务器配置均经过真实 `OcrModule` 链路与原生覆盖检查。服务器配置的两张覆盖图无文字截断，正文保持一段，控件保持独立边界。安装包中的 Windows OCR 另经四组中英截图和清晰弹窗验证，应用监管的实际 OCR 子进程进入就绪状态。完整应用的真实 NMT 截屏链路分别验证显式英语与自动语言。

离线回归使用保存的真实 OCR 输出，执行 `python -m pytest tests/fidelity`。真实完整链路分别运行 `python -m tests.fidelity.live rapid` 与 `python -m tests.fidelity.live paddle-structure`。参数比较使用 `python -m tests.fidelity.tune`。

自动化配置修改已改为按请求号确认，成功、拒绝与无变化都有精确回执。识别开始事件会清除同一会话上次失败和完成状态，重试成功后查询结果正常更新。命名管道对带换行的完整请求和未收完的请求均检查长度上限。
