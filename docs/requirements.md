# LSTtranslate 新版需求规格说明

## 1 文档目的

本文档定义从头重写的 LSTtranslate 要做什么、做到什么程度。它是后续架构设计、技术选型和验收的依据。

旧实现只作为功能参考。新版本与旧代码、旧配置文件、旧事件协议、旧界面都不兼容，旧数据也不迁移。

每条需求带一个编号，例如 `CAP-03`，架构文档和测试用例通过编号引用需求。

## 2 产品定位与用户

LSTtranslate 是一个常驻 Windows 系统托盘的屏幕翻译工具，提供两个入口：

- 截屏翻译：用热键框选屏幕区域，识别其中的文字和版面结构，在原位置弹出覆盖窗口显示译文。
- 双语互译窗口：一个常驻的小窗口，输入文字后实时显示译文。

截屏翻译使用竞速翻译机制，这是本产品的核心特色：同一段文字同时交给多个翻译引擎，谁先返回谁先显示，质量更高的引擎返回后自动替换。双语窗口只用用户选中的一个翻译服务（`BI-04`）。用户在最快的引擎返回时就能读到译文，随后译文自动升级到质量更高的版本，不需要在速度和质量之间二选一。第 5.5 节给出它的完整定义。

用户是作者本人和小范围的技术用户。他们能自己安装 Python 环境、CUDA 驱动和 Ollama，也能直接编辑配置文件。这个用户定位带来三条取舍：

1. 程序像正规软件一样通过安装程序安装和卸载（5.11 节）；安装包不带模型，模型在首次使用时下载，所以用户需要能联网完成首次配置。
2. 配置项可以直接暴露底层模型参数，不需要为普通用户做简化。
3. 首次运行引导只做环境检测和必要提示。

## 3 范围

### 3.1 本版本包含

| 领域 | 内容 |
|---|---|
| 入口 | 系统托盘、全局热键、截屏翻译、双语互译窗口 |
| 识别 | 光学字符识别（Optical Character Recognition，OCR）与完整版面结构分析：文本、标题、表格、公式、图表、图片区域；三个可选的 OCR 引擎（Windows 自带 OCR、RapidOCR、PaddleOCR），后两个按需安装 |
| 翻译引擎 | 本地神经机器翻译（Neural Machine Translation，NMT）、字典翻译、在线大语言模型（Large Language Model，LLM）接口、本地大语言模型、传统在线翻译接口、免 key 的谷歌与微软免费翻译接口 |
| 竞速翻译 | 多引擎并行、先到先显示、按优先级替换、竞速过程可视化与统计 |
| 语言 | 任意语言对，源语言可自动检测 |
| 界面 | 全部界面重新设计，采用 Windows 11 Fluent 设计语言 |
| 安装与卸载 | 当前用户安装程序、开始菜单快捷方式、Windows“应用”列表中的卸载入口、模型、词典包与 OCR 引擎按需下载、应用内更新 |
| 开发与测试 | 普通版与开发版两种构建、供测试脚本与 AI agent 使用的本机自动化接口（开发版默认开启，普通版默认关闭） |
| 平台 | Windows 11 x64 |

### 3.2 本版本之外的功能

以下功能存在于旧版本或旧版本的规划中，新版本第一版不实现：

- 复制翻译（监听剪贴板）
- 本地词典查词，即选中一个词后显示它的释义。字典翻译引擎（`ENG-08`）用到的词典包含有 ECDICT 数据，但它只把原文逐词替换成译文，不提供释义查询
- macOS 与 Linux 支持
- 翻译历史、术语表（列入第 8 章的后续版本）

## 4 术语

| 术语 | 含义 |
|---|---|
| 会话（Session） | 一次截屏翻译，或双语窗口里的一次输入。会话是取消和丢弃迟到结果的单位。 |
| 版面块（Layout Block） | 版面分析输出的一个区域，带类别（文本、标题、表格、公式、图表、图片等）和包围盒。 |
| 段（Segment） | 翻译与渲染的最小单位。文本类版面块经过段落合并后形成段；表格的每个单元格各是一个段。 |
| 引擎实例（Engine Instance） | 一个已配置的翻译引擎，例如“DeepSeek Flash”“本地 Hy-MT2”“Argos zh→en”。同一类引擎可以配置多个实例。 |
| 优先级 | 整数，数值越小优先级越高，用于决定同一段的多个译文中显示哪一个。 |
| 竞速翻译（Racing Translation） | 同一段同时交给多个引擎实例翻译，先返回的先显示，优先级更高的译文到达后替换当前显示。 |
| 胜出 | 某个引擎实例的译文成为一个段最终显示的译文。 |
| 覆盖窗口（Overlay） | 截屏翻译完成后在选区原位置弹出的译文窗口。 |
| 词典包 | 字典翻译引擎使用的数据文件，每个翻译方向一个，按需下载。 |
| 运行环境版本 | 需要下载的 OCR 引擎的推理库版本：CPU 版，或用显卡加速的 CUDA 版、DirectML 版。 |
| 双语窗口 | 双语互译窗口的简称。 |

## 5 功能需求

### 5.1 托盘与全局热键

- `TR-01` 程序启动后只出现在系统托盘，不弹出主窗口。
- `TR-02` 托盘菜单包含：截屏翻译、显示/隐藏双语窗口、设置、打开日志目录、导出诊断信息、退出。截屏翻译和双语窗口两项后面显示当前绑定的热键。
- `TR-03` 托盘菜单顶部显示 OCR 组件和每个引擎实例的状态。状态共五种：未启用、加载中、就绪、忙碌、出错。处于“出错”状态时，悬停可查看原因。
- `TR-04` 全局热键有两个：截屏翻译默认 `Alt+Q`，显示/隐藏双语窗口默认 `Alt+E`。热键在设置中修改，保存后立即生效，不需要重启。
- `TR-05` 热键注册失败时，托盘弹出通知，写明哪个热键注册失败，以及失败原因（多数情况是被其他程序占用）。
- `TR-06` 程序只允许运行一个实例。重复启动时，已运行的实例弹出通知，新进程直接退出。

### 5.2 截屏

- `CAP-01` 按下截屏热键时，程序冻结当前所有显示器的画面，并在每个显示器上覆盖一层半透明蒙版。用户在冻结画面上框选，选区内容不受框选期间屏幕变化（例如视频播放）影响。
- `CAP-02` 选区限制在鼠标按下时所在的显示器内。原因：缩放比例不同的两块屏幕拼在一起后，截图的像素密度不统一，覆盖窗口也无法同时匹配两种缩放比例。
- `CAP-03` 在缩放比例为 100%、125%、150%、200% 的显示器上，以及这些显示器的任意组合下，选区边界与截取到的物理像素误差不超过 1 像素。
- `CAP-04` 用鼠标拖动框选区域，可以随时取消截屏，默认键位见 `UI-09`。选区宽或高小于 5 个逻辑像素时视为取消。
- `CAP-05` 截图预处理可配置：灰度化，以及宽或高超过阈值时等比缩小。预处理只作用于送入 OCR 的图像，覆盖窗口的底图仍然用原图。
- `CAP-06` 新的截屏完成时，上一次截屏翻译中还没完成的识别和翻译任务全部作废，迟到的结果直接丢弃。
- `CAP-07` 多显示器的任意排布都要正确：副屏在主屏左侧或上方（坐标为负）、各屏分辨率与刷新率不同、屏幕旋转。截屏期间显示器插拔或缩放比例改变时，取消这次截屏并提示重来。覆盖窗口被拖到缩放比例不同的显示器上时，按新显示器的缩放比例重新布局，文字保持清晰（`UI-04`）。

### 5.3 OCR 与版面分析

- `OCR-01` 识别输出完整版面结构，版面块类别至少包括：正文、标题、表格、公式、图表、图片、页眉页脚。
- `OCR-02` 每个版面块包含以下信息：类别、在截图中的轴对齐包围盒（物理像素坐标）、文本、阅读顺序序号、置信度。另外三类块带额外内容：
  - 表格块：单元格网格，每个单元格有行列号、跨行跨列数、包围盒和文本。
  - 公式块：LaTeX 文本。
  - 图表块：由图表转换出的数据表。
- `OCR-03` 以下子能力可以分别开关，用来控制耗时：表格识别、公式识别、图表识别、文档方向校正、文档去畸变、文本行方向判断。
- `OCR-04` 识别语言可以配置。
  - PaddleOCR 与 RapidOCR 的自动模式使用覆盖中文、英文、日文的通用识别模型；指定语言时按该引擎的模型能力选择。
  - Windows OCR 的自动模式组合已安装的英文与一种中日文识别器；其他首选语言或只有一种可用语言时跟随系统首选。指定语言只运行该语言的系统识别器。
- `OCR-05` 文本类版面块里的文本行要合并成段落，每个段落成为一个段。合并算法做成可替换的组件，并且配一组带人工标注的样本截图作为回归测试集，衡量每次算法修改对合并正确率的影响。
- `OCR-06` 同一时刻只运行一个识别任务。识别途中有新的截屏完成时，当前任务跑完后结果直接丢弃，随后开始识别新截图。
- `OCR-07` 程序启动后在后台预加载识别模型，预加载不阻塞托盘出现。预加载完成前就触发了截屏时，覆盖窗口显示“识别模型加载中”，加载完成后自动继续这次识别。
- `OCR-08` 识别失败时，覆盖窗口显示失败原因，并提供“重试”按钮。
- `OCR-09` 提供两种识别模式：版面模式（默认）满足 `OCR-01` 至 `OCR-03`；文本模式只识别文本行，不做版面分析，所有文本归为正文块，用于追求速度的场景。6.1 节的“只开文本识别”指文本模式。
- `OCR-10` 截屏识别可以使用多个 OCR 引擎，用户在设置里选择当前使用哪一个（`OCRE-01` 至 `OCRE-09`）。不同引擎的能力不同：能给出文字位置的引擎按行返回各自的包围盒；只返回文字、不给位置的引擎，以整张截图作为一个包围盒返回全部文字，覆盖窗口把译文铺满整个选区。第一版的三个引擎都按行给出位置。
- `OCR-11` 结构识别之后、切分成段之前，有一个结构归一化中间层，由三个可配置的步骤组成，按清洗、拆分、聚合的固定顺序执行：
  1. 清洗：去掉文字为空白的行、过小或置信度过低的框、重复框。
  2. 拆分：把横跨两栏之间空白的长行拆成左右两行，只在文本模式下进行。表格里粘连的单元格第一版不拆分。
  3. 聚合：结合截图中的文字颜色、笔画粗细与间距整理文字单元。文本模式下合并连续段落（`OCR-05`）；版面模式下拆开粘连的菜单和控件，并可选合并上下紧挨、左右对齐的相邻正文块。用户可选择几何、智能段落、按句或连续正文模式，调整续行间距和句末标点。智能段落默认开启，紧密排列的多个句子保持在同一个段落中；按句模式在行尾句末标点处断开。标题、链接、按钮及分栏继续受样式和几何边界约束。

  每一步可以单独开关和调参，改动从下一次识别起生效。默认开启清洗与聚合，关闭跨栏拆分与相邻正文块合并。没有截图像素时，聚合使用几何规则。全部步骤关闭时版面块原样通过，文本模式下每个文本行单独成为一段。

### 5.3.1 OCR 引擎

- `OCRE-01` 第一版提供三个 OCR 引擎：

  | 引擎 | 识别模式 | 获取方式 | 说明 |
  |---|---|---|---|
  | Windows 自带 OCR（默认） | 只有文本模式，按行给出位置 | 不需要下载，安装程序装好即可使用 | 识别语言取决于系统已安装的 OCR 语言包 |
  | RapidOCR | 只有文本模式，按行给出位置 | 运行环境按需下载，CPU 版约 110 MB，默认模型随运行环境自带 | 用 onnxruntime 运行 PP-OCR 模型，默认的 PP-OCRv6 多语言模型覆盖中、英、日与多种拉丁字母语言 |
  | PaddleOCR | 版面模式与文本模式（`OCR-01` 至 `OCR-09`） | 运行环境与模型按需下载，CPU 版运行环境与默认模型各约 1 GB | 唯一提供表格、公式、图表识别的引擎 |

- `OCRE-02` 安装包不捆绑任何需要下载的 OCR 引擎。每个需要下载的引擎在设置里单独下载、取消、卸载，下载显示进度，失败可以重试。
- `OCRE-03` 设置的“截屏与识别”页列出全部 OCR 引擎，显示每个引擎的状态：不可用（附原因）、未安装、排队、下载中、安装中、已安装、加载中、就绪、出错（附原因与处理建议）。
- `OCRE-04` 用户可以选择当前使用的引擎，也可以关闭 OCR。切换引擎立即生效，不需要重启程序。卸载当前引擎前先确认。选用的引擎没有装好（还没下载、已卸载、更换版本失败）时，截屏识别先用 Windows 自带 OCR，选用的引擎装好后自动换回；Windows 自带 OCR 也不可用时，截屏识别不可用，直到用户另选一个引擎。
- `OCRE-05` Windows 系统没有安装任何 OCR 语言包时，Windows 自带 OCR 显示为不可用，并提示在 Windows 设置的“语言”里为对应语言添加 OCR 功能。
- `OCRE-06` OCR 进程只从本地目录加载模型，识别期间不发起网络请求；需要下载的内容只在用户点“下载”后获取（`PRV-01`）。
- `OCRE-07` 需要下载的引擎可以选择运行环境版本：PaddleOCR 有 CPU 版与 CUDA 版（NVIDIA 显卡）；RapidOCR 有 CPU 版、DirectML 版（支持 DirectX 12 的任意显卡）与 CUDA 版。程序检测本机显卡并推荐一个版本，推荐规则依次是：
  1. 有 NVIDIA 显卡，并且引擎有 CUDA 版：推荐 CUDA 版；
  2. 有支持 DirectX 12 的显卡，并且引擎有 DirectML 版：推荐 DirectML 版；
  3. 其他情况推荐 CPU 版。

  设置里在推荐版本旁写出推荐理由（例如“检测到 NVIDIA 显卡”）。换版本时只重装运行环境，已下载的模型保留。显卡驱动不满足所选版本的要求时，引擎显示为出错并说明原因。
- `OCRE-08` 每个引擎的识别流水线分成若干环节（文字检测、文字识别、文本行方向、文档方向、去畸变、版面、区域、表格、公式、图表，各引擎只用其中一部分）。每个环节可以在多个模型之间选择（例如 mobile、server，或不同版本），模型单独下载、取消与删除，设置里显示大小、覆盖的语言与是否已下载。安装引擎时只下载默认组合。选用中的模型、随运行环境自带的模型和正在下载的模型不能删除。
- `OCRE-09` 每个引擎的流水线参数可以在设置里修改：常用参数（检测阈值、输入尺寸、识别分数阈值、线程数等）直接显示；引擎的其余可调参数放在“高级参数”里，标明取值范围，可以逐项或整节恢复默认。参数改动从下一次识别起生效，需要重载模型的改动由程序自动重载（`CFG-03`）。

### 5.4 翻译引擎

- `ENG-01` 引擎分成以下几类：

  | 类别 | 代表 | 网络 | 计费 |
  |---|---|---|---|
  | 本地 NMT | Argos Translate | 不需要 | 免费 |
  | 字典翻译 | 按词典包逐词替换（`ENG-08`） | 不需要 | 免费 |
  | 在线 LLM 接口 | DeepSeek、OpenAI 及其他 OpenAI 兼容服务 | 需要 | 按 token 计费 |
  | 本地 LLM | Ollama、llama.cpp server | 不需要 | 免费 |
  | 传统在线翻译接口 | DeepL、Google Cloud Translation、百度翻译开放平台 | 需要 | 按字符计费或有免费额度 |
  | 免费在线翻译接口 | 谷歌翻译与微软翻译的免 key 接口（`ENG-09`） | 需要 | 免费 |

  第一版实现上表列出的全部代表。Ollama 和 llama.cpp server 都提供 OpenAI 兼容接口，所以本地 LLM 和在线 LLM 共用同一个协议实现，区别只在默认的并发数、超时和计费标记。
- `ENG-02` 每类引擎都可以配置多个实例。每个实例有独立的名称、启用开关、优先级、标识颜色、适用语言对、单个任务的时限，以及该类引擎特有的参数（例如接口地址、模型名、API key、提示词、温度）。各实例的优先级两两不同；配置中出现重复的优先级时，按实例在列表中的顺序重新编号。
- `ENG-03` 每个引擎实例声明自己支持哪些语言对，调度器只把任务派给支持该语言对的实例。本地 NMT 的模型以英语为中心：缺少直连模型、但“源语言→英语”和“英语→目标语言”两个模型都已安装时，经英语中转翻译。
- `ENG-04` LLM 引擎按批提交，具体要求如下：
  1. 一批包含多个段，每批的最大字符数可以配置。
  2. 每批同时附上整个会话的原文作为上下文，让同一张截图里的术语译法保持一致。
  3. 要求模型按段号返回结构化结果，请求数从“每段一次”降到“每批一次”。
  4. 接口支持流式返回时，每解析出一个完整的段就立即交给竞速合并，不等整批结束。
  5. 返回结果整体无法解析，或缺少部分段时，这些段自动退回逐段请求。
- `ENG-07` LLM 引擎实例可以开启“附带截图”：截屏翻译时，把截图连同识别出的文字一起发给模型，让模型参考画面理解上下文、纠正识别错误。这个选项默认关闭，开启时设置里明确提示“截图会发送给该服务”（`PRV-01`）。截图发送前等比缩小到可配置的最大边长。模型不支持图片输入时，该实例的尝试以“模型不支持图片”失败，提示用户关闭这个选项。双语互译窗口没有截图，不受影响。
- `ENG-05` 每个引擎实例都可以配置超时、重试次数和最大并发数。收到限流响应（HTTP 429）时按指数退避重试。
- `ENG-06` 一个引擎实例的故障（网络中断、key 无效、模型缺失）只让这个实例进入“出错”状态，其他实例照常参与竞速。
- `ENG-08` 字典翻译引擎用已安装的词典包离线逐词查词，几毫秒内给出粗译，在竞速里承担“最先出结果”的角色。具体要求：
  1. 每个翻译方向一个词典包，在设置的“模型”页和首次运行引导里按需下载与删除（`MOD-05`）。装好或删掉词典包后立即生效，不需要重启任何进程。
  2. 用空格分词的语言以词为单位查词，先试至多 3 个词的短语，再试单个词；中文和日文按词典包里的词条做正向最长匹配。查不到的词原样保留。
  3. 一段文字里有词却一个都查不到时，这一段以“查不到”失败，让其他引擎胜出，不把原文当作译文显示。只含数字和标点的段原样返回。
  4. 可选“经英语中转”：两端都不是英语时，依次用“源语言→英语”和“英语→目标语言”两个包。默认关闭。
  5. 词典数据的署名在设置的“模型”页与首次运行引导里可见，安装包附带第三方声明与许可证全文。
- `ENG-09` 谷歌翻译与微软翻译的免费接口不需要 API key。这两个接口没有公开文档，可能变动或限流，谷歌翻译在中国大陆不可用；设置里的说明写明这几点，以及启用后要翻译的文本会发送给对应的服务。单次请求最多 100 段、5000 个字符。
- `ENG-10` 配置文件不存在时生成的默认引擎列表如下，需要 API key 的引擎不在其中：

  | 优先级 | 实例 | 默认状态 |
  |---|---|---|
  | 1 | 本地 NMT（Argos） | 启用 |
  | 2 | 谷歌翻译（免费） | 不启用（`PRV-01`） |
  | 3 | 微软翻译（免费） | 不启用（`PRV-01`） |
  | 4 | 字典翻译 | 启用 |

  已有配置文件的用户不会自动得到新加入的默认实例，要在设置的翻译引擎页自己添加。

### 5.5 竞速翻译与调度

竞速翻译让每个段同时在多个引擎实例上翻译。各类引擎的速度与质量呈反向关系：字典翻译几毫秒出结果，只是逐词替换；本地 NMT 在本机几百毫秒内出结果，译文已经成句；在线 LLM 要经过网络往返和逐 token 生成，返回最慢、质量最高；传统在线接口与免费在线接口居中。竞速的效果是：用户先读到最快的译文，等质量更高的译文到达后，显示的内容自动替换。

下面是一个段在三个实例上竞速的时间线。三个实例的优先级是：DeepSeek 为 1（最高），DeepL 为 2，Argos 为 3。

| 时刻 | 事件 | 显示的译文 |
|---|---|---|
| 0 秒 | 段派发给三个实例 | 原文 |
| 0.3 秒 | Argos 返回（优先级 3） | Argos 译文 |
| 1.2 秒 | DeepL 返回（优先级 2，高于当前的 3） | DeepL 译文 |
| 2.1 秒 | DeepSeek 返回（优先级 1，高于当前的 2） | DeepSeek 译文，本段竞速结束 |

如果 DeepSeek 在 0.8 秒先于 DeepL 返回，显示会直接从 Argos 译文换成 DeepSeek 译文。此时 DeepL 的结果已经不可能替换显示，它的任务被取消（`RACE-05`）。

- `RACE-01` 一次截屏或一次双语窗口输入形成一个会话。同一入口开始新会话时，旧会话还没完成的任务全部取消，迟到的结果直接丢弃。
- `RACE-02` 会话里的每个段并行派发给所有满足两个条件的引擎实例：已启用，且支持这个语言对。派发时不等待任何实例，各实例之间没有先后顺序。双语窗口只派发给用户选中的那一个实例（`BI-04`）。
- `RACE-03` 每个段只显示当前优先级最高的成功译文。合并规则：
  1. 先返回的译文先显示，不等待更高优先级的引擎。
  2. 更高优先级的译文到达后替换当前显示。
  3. 优先级相同或更低的译文到达时，只记录下来，不替换当前显示。
- `RACE-04` 失败的结果不覆盖已有译文。一个段在所有实例上都失败时，显示原文；失败信息纳入竞速记录与统计。
- `RACE-05` 一个段的竞速在“显示已定”时结束：所有优先级高于当前胜出者的实例都已返回、失败或被取消，之后再到达的结果都不会改变显示。没有成功结果时，所有实例都结束才算显示已定。某个段一旦有更高优先级的实例成功返回，比它优先级低的同段任务都被取消，节省算力和费用：
  - 还在排队、没有开始的任务在开始执行前取消；
  - 已经在执行的任务也取消：本地 NMT 向推理进程发送取消消息，在线引擎关闭 HTTP 请求；
  - 一个批量任务里有多个段时，只有其中还没出结果的段都已被更高优先级的译文覆盖，才取消这个任务；还有段需要它时，任务继续执行。

  被取消的尝试记为“已取消”，不算失败。取消不改变最终显示的译文：被取消的实例优先级低于当前胜出者，即使照常完成，它的结果也不会替换显示。
- `RACE-06` 竞速过程的记录与显示：
  - 每个段记录每个参赛实例的状态（排队、翻译中、完成、失败、已取消）和耗时。
  - 译文被替换时播放一次不超过 150 毫秒的淡入过渡，让用户看到译文已经升级，同时不打断阅读。
- `RACE-07` 竞速统计：按引擎实例累计以下数据，在设置的“竞速”页显示，用于调整优先级和启用哪些实例。统计只计入真正执行过并给出结果（成功或失败）的尝试，命中缓存的和被取消的尝试都不计入。调度器会取消大量低优先级实例的尝试（`RACE-05`），把它们计入会压低这些实例的胜出率；执行中被取消的尝试也不算失败，不计入失败率。
  - 执行段数
  - 胜出次数（成为最终显示译文的次数）
  - 结果耗时的中位数和第 95 百分位数。结果耗时指从段派发到该实例返回这一段的结果；批量和流式引擎里，排在后面的段的耗时包含前面各段的处理时间，这正是用户看到这一段译文时实际等待的时间
  - 失败率
- `RACE-08` 译文缓存的键由五项组成：原文、源语言、目标语言、引擎实例、该实例影响译文的配置（模型、提示词、温度等）。换模型或改提示词后，旧译文不会被误用。命中缓存的实例直接以耗时 0 参加竞速，不再发请求。缓存跨会话、跨重启保留，容量上限可以配置。
- `RACE-09` 源语言设为“自动”时，调度器对每个段做语言检测。检测结果与目标语言相同的段不参加竞速，直接显示原文。只有数字、符号或一个字母的段（例如“•”“☆4”）没有可翻译的文字，标为“无需翻译”，直接显示原文。字母少或检测置信度低的拉丁字母段（例如界面上的 Star、Code、Wiki），源语言取同一张截屏里拉丁字母长文本的检测结果中最多的那种语言；截屏里没有这样的长文本时按英语处理。整段真正的外语长文本仍按它自己的检测结果翻译。
- `RACE-10` 截屏翻译和双语窗口各自配置目标语言。双语窗口还支持“互译对”规则：配置一对语言 A 和 B 后，检测到 A 就译成 B，检测到 B 就译成 A。

### 5.6 截屏翻译覆盖窗口

- `OV-01` 截屏完成后，在选区原位置立即弹出无边框、置顶的覆盖窗口，尺寸与选区相同。识别完成前，窗口显示“识别中”。
- `OV-02` 窗口底图是选区截图经模糊和调亮（或调暗）处理后的图像。按底图平均亮度自动选择文字颜色：亮底用黑字，暗底用白字。
- `OV-03` 各类版面块的渲染方式：

  | 类别 | 渲染方式 |
  |---|---|
  | 正文、标题、页眉页脚 | 在包围盒内渲染译文，字号自动适配包围盒，并且不超过原文在同一包围盒里能用的最大字号 |
  | 表格 | 保留网格线，每个单元格内渲染该单元格的译文；没开表格识别、没有单元格网格时，在每个文本行的位置渲染该行的译文 |
  | 公式 | 显示原图，不翻译 |
  | 图片 | 显示原图；图片里识别出的文本行，在原图上逐行渲染译文 |
  | 图表 | 显示原图；点击后展开图表转换出的数据表，表内文字翻译；没有数据表时按图片的方式逐行渲染译文 |

- `OV-04` 更新按段增量进行：某个段的译文变化时只重绘这个段，并按 `RACE-06` 播放过渡。
- `OV-05` 窗口里显示的原文或译文可以逐字选中，用系统标准的复制键（`Ctrl+C`、`Ctrl+Insert`）复制选中的文字。窗口内的操作如下，默认键位见 `UI-09`：

  | 操作 | 效果 |
  |---|---|
  | 切换原文与译文 | 在译文和原文之间切换 |
  | 拖动窗口 | 窗口跟随鼠标移动 |
  | 缩放整张图 | 用滚轮以光标为中心缩放，底图与译文一起缩放，窗口尺寸随之改变 |
  | 放大、缩小 | 用键盘以窗口中心为锚点缩放，每次的步长与滚轮转过一格相同 |
  | 还原大小 | 回到截屏时的大小 |
  | 固定在最上层 | 固定或取消固定；未固定时，窗口失去焦点后自动关闭 |
  | 选择文字 | 拖选时从按下处的字符选到当前位置的字符，选的是当前显示的文字（译文或原文）；可以跨段，跨段时按段的阅读顺序包含中间各段的全部文字。同一按键双击选中一个词，三击选中整段；单击时清除选中，点在图表上时展开或收起它的数据表 |
  | 关闭 | 关闭窗口 |

  复制键复制选中的文字，跨段时段与段之间换行；没有选中文字时复制键不起作用。切换原文与译文时清除选中。复制键是系统的标准行为，不在 `UI-09` 的键位表里。

- `OV-06` 已废止：覆盖窗口的引擎详情浮窗已移除。
- `OV-07` 窗口角落显示进度：显示已定（`RACE-05`）的段数和总段数。

### 5.7 双语互译窗口

- `BI-01` 按热键显示或隐藏窗口。标题栏的关闭按钮可用，关闭等同于隐藏。窗口不在任务栏占按钮，从托盘或热键唤出。窗口的位置、大小、置顶状态、手动选择的语言和选中的翻译服务在关闭后保留，下次打开时恢复。
- `BI-02` 窗口分为输入区和译文区，两区的排列方向（上下或左右）可以设置。
- `BI-03` 源语言默认自动检测，目标语言按互译对规则（`RACE-10`）自动选择。两者都可以手动指定，手动指定后不再自动切换，直到用户恢复为“自动”。
- `BI-04` 双语窗口只用一个翻译服务。窗口顶部的“翻译服务”下拉框列出启用的引擎实例，按优先级排列，计费的实例标“计费”，出错的实例不能选。输入停顿 400 毫秒后自动用选中的服务翻译，停顿时长可以配置；选中的是计费服务或免费在线接口时，每次停顿都会把文本发给对应的服务。`Ctrl+Enter` 立即翻译。选中的服务被停用、删除或出错时，窗口提示并改用列表里第一个可用的服务，它恢复后换回。
- `BI-05` 译文区显示选中服务的译文。译文区下方的状态行说明翻译失败的原因与处理建议、服务不支持语言对，或服务回退的情况；没有要说明的情况时不显示。
- `BI-06` 长文本按段落拆分，与截屏翻译共用会话、语言检测、互译对和缓存规则（`RACE-01`、`RACE-08` 至 `RACE-10`），段落级增量显示。每段只交给选中的一个服务，没有优先级替换。
- `BI-07` 提供以下按钮：复制译文、交换源语言与目标语言、清空、置顶。“复制译文”按钮复制全部译文；译文区的文字可以选中，用系统标准的复制键（`Ctrl+C`、`Ctrl+Insert`）复制选中的部分。复制没有单独的快捷键。

### 5.8 设置与配置

- `CFG-01` 设置窗口包含以下内容：热键、截屏翻译与双语窗口的语言设置、引擎实例的增删改与优先级排序、竞速统计、OCR 子能力与推理设备、截图预处理、界面主题与语言、日志级别。设置窗口的页面结构见 `UI-05`。
- `CFG-02` 配置文件是人可读的文本文件，可以直接编辑。程序启动时校验每个字段，遇到非法值时报告字段名和原因，并对这个字段使用默认值，其他字段不受影响。
- `CFG-03` 修改即时生效。热键、引擎实例、优先级的修改保存后立即生效。推理设备、识别模型这类需要重新加载推理组件的修改，由程序自动重载，用户不需要重启程序。
- `CFG-04` API key 与普通配置分开存放，任何日志和诊断导出里都不出现 API key。
- `CFG-05` 界面语言支持简体中文和英文。
- `CFG-06` 数据目录可以在设置的“常规”页更改。数据目录存放配置、译文缓存、统计、日志和界面状态，默认是安装版的 `%LOCALAPPDATA%\LSTtranslate`、源码版的 `data/`。
  1. 配置文件本身在数据目录里，所以选好的目录记在数据目录之外的位置文件里：安装版是 `%APPDATA%\LSTtranslate\location.json`，源码版是 `data/location.json`。启动时数据目录的优先级是：命令行参数 `--data-dir`、环境变量 `LST_DATA_DIR`、位置文件、默认位置。前两者指定了数据目录时，设置里不能更改，并说明原因。
  2. 新目录必须写得进文件。程序在新目录里实际创建、改名、删除一个文件来检查，权限不足、介质只读、程序以 Low 完整性运行时都拒绝更改，并显示系统给出的原因。新目录不能在当前数据目录里面。
  3. 更改前确认，确认框里有“把现有数据复制到新位置”，默认勾选。复制在后台进行并显示进度；新目录里已有同名内容或空间不够时拒绝，复制失败时删除复制了一半的内容，数据目录不变。
  4. 更改在重启程序后生效。设置里显示“重启后改用”的新目录和“立即重启”按钮，点它后程序退出并以同样的命令行重新启动。
  5. 位置文件指向的目录在启动时无法使用（例如所在的磁盘没有接上）时，本次改用默认位置并通知用户。
- `CFG-07` 模型目录可以在设置的“常规”页更改（`MOD-04`）。模型目录存放本地翻译模型、OCR 模型与 OCR 引擎的运行环境、词典包和显卡运行库，默认是数据目录下的 `models`，各类内容在其中的子目录名固定（`nmt`、`ocr`、`engines`、`dict`、`runtimes`）。选好的目录写在配置的 `[storage].models_dir`。
  1. 新目录的写入检查与 `CFG-06` 相同，新目录不能在当前模型目录里面。
  2. 更改前确认，确认框里有“把现有模型移动到新目录”，默认勾选。移动前停下本地翻译与文字识别进程，进行中的下载随之取消；移动在后台进行并显示进度。新旧目录在同一个磁盘上时直接改名；不在同一个磁盘上时先复制，配置写好之后再删除旧目录。
  3. 移动或写配置失败时，模型移回原处，模型目录不变，设置里显示原因。
  4. 完成后程序按新目录重新扫描模型、重新启动本地翻译与文字识别进程，不需要重启程序。手工改了配置文件里的 `[storage].models_dir` 时同样按新目录重新加载，但不移动文件。

### 5.9 模型管理

- `MOD-01` 本地 NMT 模型：设置里列出所有可下载的语言对模型，标明哪些已安装，支持下载和删除，下载时显示进度。
- `MOD-02` OCR 模型：安装引擎时下载默认组合（`OCRE-02`），其余模型在设置的“截屏与识别”页按环节单独下载（`OCRE-08`），都不在启动时自动下载。
- `MOD-03` 本地 LLM 由 Ollama 或 llama.cpp 自己管理。程序只读取它们已有的模型列表，供用户在引擎实例中选择。
- `MOD-04` 模型存放目录可以配置，运行中更改后立即生效（`CFG-07`）。本地翻译模型另外可以单独指定目录（`[nmt].model_dir`，设置的“模型 › 本地翻译模型”页），用来直接使用别处已有的 `.argosmodel` 文件；留空时用模型目录下的 `nmt`，更改模型目录时不移动单独目录里的文件。
- `MOD-05` 词典包：设置的“模型”页列出可下载的词典包，显示大小、许可证、署名与是否已安装，支持下载、取消和删除，与本地 NMT 模型共用一个下载队列。下载完成后校验 SHA-256，校验不通过时丢弃。
- `MOD-06` 本地翻译的显卡运行库（NVIDIA cuBLAS 12）：
  1. 安装包不带它，设置的“模型”页按需下载，可以取消和删除，下载完成后校验 SHA-256。
  2. 页面显示下载大小、版本、本机检测到的 NVIDIA 显卡，以及本地翻译当前实际使用的设备。没有检测到 NVIDIA 显卡时说明下载后用不上，但不禁止下载。
  3. 推理设备可以选“自动”“仅 CPU”或“NVIDIA 显卡”，修改后本地翻译进程自动重启。
  4. 本地翻译进程按完整路径加载运行库，不按 PATH 搜索。
  5. 装好或删除运行库后，本地翻译进程自动重启，不需要重启程序。

### 5.10 界面

新版本的全部界面重新设计，旧版本的窗口布局、控件和交互逻辑都不沿用。本节的需求适用于设置窗口、双语窗口、托盘菜单、通知和首次运行引导。覆盖窗口和截屏蒙版的外观由它们各自的需求（`OV-02`、`CAP-01`）决定。

- `UI-01` 设计语言统一采用 Windows 11 的 Fluent 风格：圆角、Mica 或亚克力背景材质、跟随系统强调色、Segoe UI Variable 字体与 Fluent 图标。原因：程序只运行在 Windows 11 上，与系统外观一致时用户不需要适应新的视觉规则。
- `UI-02` 深色和浅色主题默认跟随系统设置，也可以在设置中手动指定。切换主题时界面立即刷新，不需要重启。
- `UI-03` 在 100% 至 200% 的缩放比例下，所有文字和图标清晰，界面不出现模糊的位图。图标全部使用矢量格式。
- `UI-04` 所有窗口支持在不同缩放比例的显示器之间拖动，拖到新显示器后按新显示器的缩放比例重新布局。
- `UI-05` 设置窗口采用左侧导航、右侧内容的布局。导航分两级，一级项展开后显示二级页面，同一时间只展开当前分支：
  1. 常规：界面语言、主题、日志级别，存储位置（数据目录与模型目录，`CFG-06`、`CFG-07`）
  2. 热键与键位
     1. 全局热键：截屏翻译与双语窗口的热键
     2. 截屏蒙版、覆盖窗口、双语窗口：各自窗口里的操作键位（`UI-09`），每页只列出这个窗口的操作
  3. 截屏与识别
     1. OCR 引擎：引擎的安装、运行环境版本与选择（`OCRE-01` 至 `OCRE-07`）
     2. Windows OCR、RapidOCR、PaddleOCR：各自引擎的运行环境，识别流水线的模型与参数（`OCRE-08`、`OCRE-09`），可选环节（方向校正、去畸变、表格、公式、图表、版面区域检测）的单独开关
     3. 结构归一化（`OCR-11`）
     4. 截图与识别选项：OCR 开关、识别模式、推理设备、识别语言、截图预处理、目标语言
  4. 翻译引擎：引擎实例列表，拖拽排序即设定优先级，点击实例展开详细参数，并提供“测试连接”按钮
  5. 竞速：双语窗口设置、竞速统计（`RACE-07`）
  6. 模型
     1. 本地翻译模型：本地翻译模型的单独目录（`MOD-04`）、本地 NMT 模型的下载与删除（`MOD-01`）
     2. 显卡加速：推理设备、显卡运行库（`MOD-06`）
     3. 词典：词典包的下载与删除（`MOD-05`）
  7. 关于与诊断：版本、依赖与 GPU 信息、导出诊断信息

  窗口记住上次停留的子页。`Ctrl+1` 至 `Ctrl+7` 切到第 n 个一级项，`Ctrl+Tab` 按子页顺序循环（`UI-07`）。

### 5.11 安装与卸载

- `INS-01` 提供 Windows 安装程序，按当前用户安装，默认安装到 `%LOCALAPPDATA%\Programs\LSTtranslate`，可以改目录。安装和卸载都不需要管理员权限。
- `INS-02` 安装完成后，开始菜单里有程序的快捷方式。安装时可以选择两项：创建桌面快捷方式（默认不选）、登录 Windows 时自动启动（默认不选）。安装完成页提供“立即运行”。
- `INS-03` 安装包是精简包：包含程序和主进程运行环境，不含任何模型文件，也不含需要下载的 OCR 引擎（`OCRE-02`）。首次运行时，首次运行引导（`UI-08`）列出所选语言对需要的本地 NMT 模型和词典包，由用户确认后下载；下载显示进度，可以取消，失败后可以重试（`MOD-01`）。截屏识别默认使用不需要下载的 Windows 自带 OCR。没有下载模型时，程序照常启动，没有模型的功能在托盘和设置里显示原因。
- `INS-04` 程序出现在 Windows 的“设置 → 应用 → 已安装的应用”里，显示名称、版本、发布者和图标，可以从那里卸载。
- `INS-05` 安装、升级或卸载时程序正在运行：安装程序提示用户，由用户确认后关闭程序再继续。
- `INS-06` 卸载删除程序文件、快捷方式和登录自启项，然后询问是否同时删除用户数据：配置、缓存、统计、日志、已下载的模型，以及凭据管理器中本程序保存的 API key。用户在设置里另选的数据目录与模型目录（`CFG-06`、`CFG-07`）里可能还有别的文件，卸载只删除其中由程序创建的内容，再删除记录数据目录的位置文件。选“否”时这些数据全部保留，位置文件也保留，重新安装后继续使用。
- `INS-07` 覆盖安装新版本（升级）时保留全部用户数据，不重复下载已有的模型。
- `INS-09` 程序可以检查新版本（`UPD-01` 至 `UPD-06`）。
- `INS-08` 源码运行方式继续保留，供开发使用：默认数据目录在程序目录下的 `data/`。安装版的默认数据目录在 `%LOCALAPPDATA%\LSTtranslate`，两者互不影响，各自的位置文件也分开（`CFG-06`）。

### 5.12 应用更新

- `UPD-01` 新版本从项目的 GitHub Releases 获取。每个版本附带安装包和它的 SHA-256 校验文件。
- `UPD-02` 程序启动后在后台定期检查新版本，默认每 24 小时一次，可以在设置里关闭自动检查。检查失败不打扰用户，只写日志。
- `UPD-03` 托盘菜单和设置的“关于”页提供“检查更新”。手动检查时，无论结果如何都告诉用户：已是最新、发现新版本或检查失败的原因。
- `UPD-04` 发现新版本时通知一次（同一版本不重复通知），用户可以查看发布说明，确认后下载；下载显示进度，完成后校验 SHA-256，校验不通过时丢弃并提示。
- `UPD-05` 用户确认安装后，程序启动新版本的安装包做覆盖安装并退出；安装完成后自动重新启动程序。升级保留全部用户数据（`INS-07`）。
- `UPD-06` 可以选择是否接收预发布版本。源码运行时只检查、不下载也不安装。

### 5.13 开发版与自动化接口

自动化接口供同一台电脑上以当前用户身份运行的程序（测试脚本、AI agent）驱动并检查程序的真实交互，不模拟操作系统的键盘鼠标。设计见架构文档第 16 章，给 agent 的使用说明见 `docs/automation.md`。

- `DEV-01` 程序提供自动化接口，设置的“关于与诊断”页有它的开关。开关的说明写明风险：开启后同一台电脑上以当前用户身份运行的程序可以控制本程序，包括截屏、读取识别与翻译结果、修改设置、更改数据目录与模型目录、重启和退出程序。
- `DEV-02` 程序有两种构建类型：普通版与开发版。两者的代码与功能完全相同，唯一的区别是自动化接口开关的默认值：普通版关闭，开发版开启。用户在设置里打开或关闭过开关之后，以配置为准，换装另一种构建类型也不变。关于页的版本号后面注明“开发版”。安装版的构建类型由安装包决定；源码运行时默认是普通版，可以用命令行参数 `--flavor dev` 或环境变量 `LST_FLAVOR=dev` 切成开发版。
- `DEV-03` 开关在运行中切换立即生效，不需要重启。开启期间托盘图标的悬停提示写“自动化接口已开启”；本次运行第一次开启时弹出一条通知。
- `DEV-04` 接口只在本机可用，只有当前用户的程序能连接，其他用户、远程计算机与 Low 完整性的进程都连不上。接口不提供执行任意代码、读写任意文件的功能。日志只记方法名、结果与耗时，不记截屏内容、原文与译文（`PRV-02`）。
- `DEV-05` 截屏翻译与覆盖窗口：按屏幕上的矩形截屏，可以跳过蒙版直接截取（矩形可以跨屏），也可以打开真实的蒙版并模拟框选；等识别与翻译全部定下来后取回识别出的块与段、当前显示的译文、来自哪个服务、各服务的状态与耗时、跳过原因和覆盖窗口的状态；在覆盖窗口上选字并取出选中的文字，切换原文与译文、缩放、固定、关闭；把覆盖窗口、蒙版或设置窗口的画面存成图片。
- `DEV-06` 键位与设置：读取与修改任意一节配置并告知修改是否生效、被拒绝的原因；读取、修改与恢复默认的窗口键位（`UI-09`）；按当前键位向蒙版与覆盖窗口发送按键或鼠标操作，验证改过的键位是否生效；打开设置窗口的指定页面，读取导航菜单。
- `DEV-07` 存储位置与重启：更改数据目录与模型目录（`CFG-06`、`CFG-07`），判断规则与设置页相同，并等到复制或移动完成；立即重启与退出程序。会移动文件或重启程序的操作要求调用方显式确认。程序重启后接口在新进程里重新可用，客户端可以等待并重新连上。提供命令行客户端（源码运行与安装版各一种调用方式），结果以 JSON 输出，出错时退出码非 0。
- `DEV-08` 每个版本同时发布普通版与开发版两个安装包，开发版安装包名为 `LSTtranslate-<版本>-dev-setup.exe`，各自带 SHA-256 校验文件。两个安装包互相覆盖安装，安装后的启动方式相同。应用内更新（`UPD-01` 至 `UPD-06`）只下载与当前构建类型相同的安装包。

## 6 非功能需求

### 6.1 性能

下表中的数值是第一版的验收目标。测量条件：Windows 11、NVIDIA GPU，或 8 核 CPU；选区 1920×1080 物理像素，内容为普通文档页面。

| 指标 | 目标 |
|---|---|
| 程序启动到托盘图标出现 | ≤ 2 秒 |
| 按下截屏热键到蒙版出现 | ≤ 200 毫秒 |
| 松开鼠标到覆盖窗口出现 | ≤ 100 毫秒（此时显示“识别中”） |
| 识别完成（文本模式，`OCR-09`） | GPU ≤ 1.5 秒，CPU ≤ 4 秒 |
| 识别完成到第一段竞速译文出现（参赛实例中有本地 NMT） | ≤ 1 秒 |
| 双语窗口停顿触发到第一个竞速译文出现（200 字以内，参赛实例中有该语言对的直连本地 NMT 模型） | ≤ 500 毫秒 |
| 某个引擎实例返回结果到界面开始显示新译文（过渡动画的第一帧） | ≤ 50 毫秒 |
| 设置窗口打开 | ≤ 300 毫秒 |

开启表格、公式、图表识别后的耗时不设上限，但必须在会话耗时日志（`OBS-02`）里分项记录。

### 6.2 稳定性与故障隔离

- `REL-01` OCR 和本地模型推理崩溃（包括原生库导致的进程级崩溃）不能让托盘和界面退出。推理组件崩溃后自动重启，托盘弹出通知说明崩溃发生在哪个组件。
- `REL-02` 推理依赖之间的冲突（例如 Paddle 与 PyTorch 的 DLL 加载顺序冲突）只能影响推理组件，不能影响界面启动。推理组件起不来时，托盘和设置窗口照常可用，用户可以在设置里改配置后重载推理组件。
- `REL-03` 退出程序时，所有子进程和线程在 3 秒内结束，系统里不留下残留进程。
- `REL-04` 竞速进行中，以及窗口拖动、缩放、滚动期间，界面线程上单次操作的耗时不超过 16 毫秒。识别、翻译、文件读写和网络请求都在界面线程之外完成。截屏冻结和窗口首次创建只在用户触发时发生一次，分别受 6.1 节“蒙版出现”和“设置窗口打开”两项指标约束。

### 6.3 可观测性

- `OBS-01` 日志分 DEBUG、INFO、WARNING、ERROR 四个级别，按天滚动，保留天数可以配置。
- `OBS-02` 每个会话记录分段耗时：截屏、预处理、版面分析、文本识别、各子能力，以及每个引擎实例的首个结果耗时和全部完成耗时。竞速统计（`RACE-07`）的数据来自这份记录。
- `OBS-03` “导出诊断信息”生成一个压缩包，内容包括：去除 API key 的配置、Python 与依赖版本、GPU 与驱动信息、最近 3 天的日志。
- `OBS-04` 用户能看到的每条错误信息都写明具体原因和处理建议，例如“DeepSeek 返回 401：API key 无效，请在设置 → 翻译引擎中检查”。

### 6.4 隐私

- `PRV-01` 截图和识别出的文本只发送给用户启用的在线引擎实例。不需要 API key 的谷歌与微软免费接口同样属于在线引擎，默认列出但不启用（`ENG-10`），用户勾选启用后才发送文本。只启用本地引擎时，程序只发起两类网络请求：用户确认的下载（翻译模型、词典包、OCR 引擎与模型、更新安装包），以及检查新版本（`UPD-02`，只访问 GitHub 的版本列表，不附带任何用户数据，可以在设置里关闭）。
- `PRV-02` 默认不把截图和原文、译文写进日志。只有用户打开“调试记录内容”开关后，才记录文本。

### 6.5 可维护性

- `MNT-01` 截屏、OCR、竞速调度、各类引擎、覆盖窗口、双语窗口、设置、托盘各自是独立模块。模块之间只通过事件和共享的契约类型通信，模块依赖规则用自动化检查强制执行。
- `MNT-02` 新增一类翻译引擎时，只需要实现引擎接口并注册，竞速调度和界面代码不需要改动。
- `MNT-03` 界面层只负责显示和收集用户操作，不包含业务逻辑。竞速合并、会话管理、配置校验都在界面层之外实现，并且可以脱离界面单独测试。
- `MNT-04` 非界面模块都有单元测试。竞速合并规则（`RACE-03` 至 `RACE-05`）的测试覆盖到达顺序、失败和取消的全部组合。段落合并（`OCR-05`）和版面结果转换有基于样本截图的回归测试。
- `MNT-05` 所有公共接口都有类型标注，静态类型检查零错误。

### 6.6 运行环境

- 操作系统：Windows 11 x64，22H2（build 22621）及以上。Mica 背景材质（`UI-01`）从这个版本起才可用。
- 运行方式：安装版通过安装程序安装（5.11 节）；源码版用于开发，源码加 Python 虚拟环境运行。
- 硬件：显卡可选。NVIDIA 显卡可以用 OCR 引擎的 CUDA 版，支持 DirectX 12 的其他显卡可以用 RapidOCR 的 DirectML 版（`OCRE-07`）。只有 CPU 时，全部功能照常可用，只是速度按 6.1 节的 CPU 目标计算。

## 7 关键流程

### 7.1 截屏翻译

1. 用户按下截屏热键，程序冻结各显示器画面并显示蒙版（`CAP-01`）。
2. 用户在一个显示器内框选后松开鼠标，程序截取选区、创建新会话，并作废上一个截屏会话（`CAP-06`、`RACE-01`）。
3. 覆盖窗口在选区原位置弹出，显示模糊底图和“识别中”（`OV-01`、`OV-02`）。
4. 预处理后的图像送入 OCR，输出版面块；版面块经结构归一化后切分成段（`OCR-01`、`OCR-05`、`OCR-11`）。
5. 覆盖窗口按版面块渲染原文，此时用户已经可以阅读和复制原文（`OV-03`）。
6. 调度器对每个段做语言检测，并把段同时派发给所有符合条件的引擎实例，竞速开始（`RACE-02`、`RACE-09`）。
7. 译文陆续返回，按优先级合并，覆盖窗口增量刷新并播放过渡（`RACE-03`、`OV-04`）。
8. 每个段在显示已定时竞速结束；已经不可能改变显示的任务被取消，排队中的在开始执行前取消，执行中的随即中断（`RACE-05`）。
9. 本次会话各实例的耗时和胜出情况写入竞速统计（`RACE-07`、`OBS-02`）。

### 7.2 双语互译窗口

1. 用户按下热键，双语窗口在上次关闭的位置出现（`BI-01`）。
2. 用户输入文字。输入停顿后，程序把文字按段落拆分并创建新会话，旧会话被取消（`BI-06`、`RACE-01`）。
3. 程序检测源语言，并按互译对规则确定目标语言（`BI-03`、`RACE-10`）。
4. 段交给用户选中的翻译服务（`BI-04`）。
5. 译文按段落增量显示，失败或不支持语言对时状态行说明原因（`BI-05`）。

## 8 版本规划

第一版实现第 5、6 章的全部需求。

以下功能列入后续版本，排列顺序就是建议的实现顺序：

1. 翻译历史：保存每个会话的截图、原文、各实例译文和竞速记录，可以搜索和重新打开。
2. 术语表：用户维护“原文→译文”对照表，翻译时注入 LLM 提示词，并在 NMT 输出上做替换。
3. 计费引擎用量统计：按实例统计 token 数或字符数。
4. 复制翻译。
