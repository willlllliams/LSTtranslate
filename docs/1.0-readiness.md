# 1.0 发布验收

## 交付范围

1.0.0 交付 Windows 屏幕翻译工具及普通版、开发版两种安装包。验收沿截图、识别、分段、翻译、覆盖、配置保存、重启和更新的实际链路进行。原始四张 PNG、98 个人工文字单元与参考译文继续作为当前截图任务的验收依据。

普通版和开发版共享应用实现，构建标记决定自动化接口的默认开关，用户保存的显式设置优先。两种安装包及其 SHA-256 文件进入同一个正式 Release；发布标签与安装包内源码必须对应同一提交。

## 识别与覆盖

1. 在原始无损截图上运行生产 OCR 子进程与 `OcrModule`，检查文字内容、单元召回、控件粘连、拆碎和框位置。缓存必须绑定源图哈希。
2. 默认模型在两页上的内容与分段指标不得低于已发布 beta.3。选定的高质量配置应完整召回标注单元，逐张检查原生 Windows 覆盖图的文字完整性、字号、换行与层级。
3. 服务器模型的词框后处理应保持可用原始文字的阅读顺序；检测漏字与后处理顺序错误分别量化。检测输入尺寸、外扩和模型组合保留可复现实验。
4. 识别成字母或数字的图标、评分和按钮要结合原图检查，避免错误译文覆盖图形。新增过滤规则必须保留真实短词、计数、品牌名与正文。
5. 检查默认识别语言与显式选择语言的实际行为，验收报告分别记录语言配置。使用固定参考译文检查布局，使用真实翻译引擎检查完整截屏链路。

## 代码与技术债

代码审核覆盖数据契约、配置校验与回执、推理进程生命周期、坐标缩放、归一化、竞速、渲染、自动化管道、下载、安装与更新。已复现的问题必须记录原因、影响、修复或保留理由；尚未完成的产品入口在说明与界面中保持一致。

识别改动同时运行既有段落样本、性质测试、图像外观边界测试、原始截图回归与真实子进程验证。严格类型、代码规范、格式及八项依赖边界检查通过后，再执行最终全量回归。全量失败需要定位，并按影响范围验证修复；最终发布证据明确区分单次全量结果与局部复测。

正式发布要求最终一次完整回归通过，条件跳过项逐项说明原因。局部复测用于定位和修复阶段，完整回归继续作为正式发布的验收条件。

## 安装、升级与发布

1. 用正式依赖清单构建两个安装包，检查启动器、主进程导入、五份带哈希的 OCR 环境清单与构建类型标记。
2. 在隔离的安装目录和数据目录中验证启动、自动化默认值、显式配置保存、重启与更新资产选择。安装与升级操作保持测试目录边界，保护现有用户数据。
3. 检查普通版与开发版的覆盖升级，以及数据目录、模型目录迁移和卸载选项。GPU 条件不可用的项目在验证记录中明确范围。
4. 设置正式版本 `1.0.0`，核对提交、标签、安装包、校验文件和发布说明。上传后逐一核对远端摘要及资产状态，再公开正式 Release。

当前审核与遗留项见 `technical-debt.md`；识别基线见 `ocr-quality.md`；服务器模型对照见 `server-ocr-analysis.md`。上述条件全部经实际结果验证后，完成 1.0 发布。
