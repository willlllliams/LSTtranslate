# 1.0 发布验收

## 交付范围

1.0.0 交付 Windows 屏幕翻译工具及普通版、开发版两种安装包。验收沿截图、识别、分段、翻译、覆盖、配置保存、重启和更新的实际链路进行。原始四张 PNG 的 98 个人工文字单元，以及 GitHub 清晰弹窗的五个文字单元与参考译文，共同约束识别与覆盖质量。新增组织页和缩略弹窗分别检查说明行与小字识别边界。

普通版和开发版共享应用实现，构建标记决定自动化接口的默认开关，用户保存的显式设置优先。两种安装包及其 SHA-256 文件进入同一个正式 Release；发布标签与安装包内源码必须对应同一提交。

## 识别与覆盖

1. 在原始无损截图上运行生产 OCR 子进程与 `OcrModule`，检查文字内容、单元召回、控件粘连、拆碎和框位置。缓存必须绑定源图哈希。
2. 默认模型在两页上的内容与分段指标不得低于已发布 beta.3。选定的高质量配置应完整召回标注单元，逐张检查原生 Windows 覆盖图的文字完整性、字号、换行与层级。
3. 服务器模型的词框后处理应保持可用原始文字的阅读顺序；检测漏字与后处理顺序错误分别量化。检测输入尺寸、外扩和模型组合保留可复现实验。
4. 识别成字母或数字的图标、评分和按钮要结合原图检查，避免错误译文覆盖图形。新增过滤规则必须保留真实短词、计数、品牌名与正文。
5. 检查默认识别语言与显式选择语言的实际行为，验收报告分别记录语言配置。使用固定参考译文检查布局，使用真实翻译引擎检查完整截屏链路。
6. GitHub 清晰弹窗正文在四种引擎下保持一个段落，标题、链接与按钮维持独立位置。段落模式、续行间距与句末标点设置可保存；覆盖窗口移除引擎详情浮窗和来源色条。

## 代码与技术债

代码审核覆盖数据契约、配置校验与回执、推理进程生命周期、坐标缩放、归一化、竞速、渲染、自动化管道、下载、安装与更新。已复现的问题必须记录原因、影响、修复或保留理由；尚未完成的产品入口在说明与界面中保持一致。

识别改动同时运行既有段落样本、性质测试、图像外观边界测试、原始截图回归与真实子进程验证。严格类型、代码规范、格式及八项依赖边界检查通过后，再执行最终全量回归。全量失败需要定位，并按影响范围验证修复；最终发布证据明确区分单次全量结果与局部复测。

正式发布要求最终一次完整回归通过，条件跳过项逐项说明原因。局部复测用于定位和修复阶段，完整回归继续作为正式发布的验收条件。

## 安装、升级与发布

1. 用正式依赖清单构建两个安装包，检查启动器、主进程导入、五份带哈希的 OCR 环境清单与构建类型标记。
2. 在隔离的安装目录和数据目录中验证启动、自动化默认值、显式配置保存、重启与更新资产选择。安装与升级操作保持测试目录边界，保护现有用户数据。
3. 检查普通版与开发版的覆盖升级，以及数据目录、模型目录迁移和卸载选项。GPU 条件不可用的项目在验证记录中明确范围。
4. 设置正式版本 `1.0.0`，核对提交、标签、安装包、校验文件和发布说明。上传后逐一核对远端摘要及资产状态，再公开正式 Release。

当前审核与遗留项见 `technical-debt.md`；识别基线见 `ocr-quality.md`；服务器模型对照见 `server-ocr-analysis.md`。上述条件全部经实际结果验证后，完成 1.0 发布。

## 1.0.0 验收结果

2026 年 10 月 23 日的验收使用 Windows 11、CPython 3.13、PySide6 6.12.0。普通版与开发版共享程序文件，安装标记分别指定构建类型。

| 项目 | 实测结果 |
|---|---|
| 完整回归 | 4554 项通过，12 项条件跳过，耗时 791.12 秒 |
| 严格类型 | 0 错误、0 警告 |
| 规范与格式 | 代码检查通过，523 份受检查文件格式一致 |
| 依赖边界 | 330 个 Python 文件、1971 条依赖，八项约束通过 |
| 服务器高质量配置 | 长边 960；两页 98 个标注单元的归一化内容、召回与独立匹配均为 100%，误合并与误拆分为零 |
| GitHub 正文 | 四种引擎均保持一段，组织页说明行完整；覆盖窗口移除引擎详情与来源色条 |
| 原生覆盖图 | 服务器两页无文字截断；使用固定参考译文检查排版 |
| 实际翻译链路 | Windows OCR 的英语与自动配置均经过真实本地 NMT、覆盖、选择与复制验证 |
| 原生安装 | 普通版默认关闭自动化，开发版默认开启；覆盖升级保留显式开关与段落设置 |
| 重启与迁移 | 实际进程重启、数据复制及模型目录移动通过，验证文件内容正确，个人文件保留 |
| 卸载与清理 | 静默卸载保留数据和位置文件；隔离的应用数据清理命令通过，真实用户凭据保留 |
| 包内识别 | 实际 OCR 子进程就绪，四组中英截图文字正确，清晰弹窗正文为一段 |
| 构建与源码 | 两个安装包、两个 SHA-256 文件；259 份包内 Python 源文件与仓库对应文件逐一一致 |

12 项条件跳过包括八项按需生成截图的测试、三项离屏平台不支持的深浅色测试，以及一项 CUDA 子进程依赖条件测试。三项深浅色测试另在原生 Windows 上运行，全部通过。CUDA 测试的子进程返回依赖错误 65，保留该条件边界。

字符指标忽略大小写、空格和标点，额外检测框仍记录。218×95 缩略弹窗存在漏字，Windows OCR 的按钮和同形字也保留系统模型限制。首次引导扩展、诊断导出、干净用户环境和不同 GPU 驱动组合的范围见 `technical-debt.md`。
